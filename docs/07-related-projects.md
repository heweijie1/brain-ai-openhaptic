# 07. 技术生态与兼容性调研

## 1. 文档定位

本文件用于记录公开技术生态的能力边界和兼容性方向。OpenHapticAI 的公开仓库定位为原创框架，不包含第三方项目源码、PCB、固件、模型文件或实验数据。

如果未来在独立分支或内部研发中引入任何第三方代码、硬件文件或模型文件，必须按对应许可证保留版权声明、NOTICE 和许可证文本。

## 2. 超声相控阵硬件生态

### 2.1 第一代工程原型

第一代硬件目标是构建 16×16 级别的 40kHz 超声相控阵原型，用于验证：

- 单点空中触觉
- 虚拟按钮
- 简单焦点移动
- 低频幅度调制
- 3-4 种基础材质触觉表达

### 2.2 第二代工程平台

第二代硬件目标是提升阵列规模、相位分辨率、功率控制和校准能力，用于验证：

- 多点时分复用
- 多材质参数库
- 更稳定的安全限制
- 自动校准
- 产品级结构和散热

## 3. 声场算法与仿真生态

OpenHapticAI 的公开实现优先建立自有抽象：

- 阵列几何模型
- 单点焦点求解
- 触觉调制参数
- 多点调度
- 安全限制
- 仿真 backend

声场求解层只暴露通用数学和设备能力接口，不绑定某一个开源或商业硬件实现。

## 4. 专业设备兼容方向

OpenHapticAI 将预留专业空中触觉设备兼容层，但公开框架不依赖任何单一商业或开源设备。

统一抽象包括：

- `DeviceProfile`
- `ArrayGeometry`
- `HapticFrame`
- `PhaseAmplitudeFrame`
- `HardwareBackend`

## 5. 空间计算生态

OpenHapticAI 面向以下空间计算入口预留接口：

- OpenXR
- Unity
- WebXR
- AR 眼镜
- 手部追踪
- 虚拟对象碰撞事件

## 6. 国产 AI 生态

OpenHapticAI 优先兼容中国 AI 生态：

- DeepSeek
- Qwen/通义千问
- 百度文心/千帆
- 智谱 GLM
- 讯飞星火
- MiniMax
- ModelScope
- MindSpore
- PaddlePaddle
- Dify / Coze / FastGPT / RAGFlow

## 7. 公开仓库策略

公开仓库只提供：

- 原创框架代码
- 通用 API
- 通用仿真
- 学习型示例
- 安全规范
- 兼容层接口

公开仓库不提供：

- 核心材质数据集
- 商业校准参数
- 内部实验数据
- 未公开硬件细节
- 第三方项目源码拷贝

## 8. 组合策略

```text
原创框架：触觉意图、触觉渲染、声场求解、仿真、安全限制
兼容生态：通过 HardwareBackend 对接不同硬件
内部资产：材质数据、实验数据、校准参数和产品硬件细节
长期目标：形成 BRAIN AI 空间触觉操作系统层
```
